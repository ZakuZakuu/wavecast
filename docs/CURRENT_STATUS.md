## 2. 产品定义（已确认）

- **定位**：轻主持的 AI 音乐电台。用户说一句想听什么，现场编排一档节目；音乐几秒内响起，后面的内容边播边生成。主持在前奏、间奏里压低音乐说话。
- **和现有产品的区别**：推荐模式是被动的；歌单、AI 智能歌单给的是一串歌；AI 音乐播客、榜单解读解读的是现成的歌单和榜单。WaveCast 从用户的一句话出发，用电台的形式讲给你听，听完的兴趣再反过来驱动“为你”推荐，形成闭环。
- **电台 = 节目的做法，话题由用户给**。五个电台：随便听 88.7、唱片行 93.1、人物志 97.4、来龙去脉 101.5、夜里 105.8。自由输入时自动匹配电台。
- **现状**：电台目前只在前端体现（常量配置 + 关键词匹配），后端还没有按电台区分生成方式，见第 8 节。
- **推荐**：登录用户的“猜你想听”是生成的节目方案（proposal），点击后才生成节目；游客首页是 5 个固定选题的“先听这几档”，同样点击后现场生成。

## 6. 初赛提交材料

- 作品名称：WaveCast；一句话：说一句想听什么，电台马上开播。
- Demo：https://wavecast.space
- 视频：概念宣传片（2 分 08 秒），右下角有“概念演示，画面为示意，功能以实际产品为准”。
- 作品介绍与创作思路（定稿，292 字）：

> 音乐软件的推荐很擅长“猜你喜欢”，但当用户想主动听点什么时，往往不知道从哪下手：歌单的主题由制作人决定，粒度未必合口味；“游戏里的某种音乐风格”这类交叉、小众的主题，也很少有人做成歌单。
>
> WaveCast 让用户说一句想听什么，就为这句话现场编排一档电台节目。选择电台作为载体，是因为它能带来音乐之外的信息：主持在前奏、间奏里压低音乐，讲歌手的故事、风格的来历，讲与听交替，按内容组织节奏。节目边播边生成，几秒就能开听。
>
> 听过的节目还会影响“为你”页，系统顺着你刚打开的兴趣继续推送新节目，让主动探索和推荐形成闭环。推荐解决“听什么”，WaveCast 解决“想听这个，却不知道怎么听”。

## 7. 已知问题（已记为 GitHub issue）

1. 前端：播放状态条在缓冲充足时仍显示“正在准备”；应只在剩余缓冲不足 45 秒时显示，其余时间显示“接下来”。
2. 生成：节目标题和主持词的语言不稳定（中文界面出现日文），应跟随界面语言，歌名人名保留原文。
3. 生成：实际时长明显短于预估（例如预估 42 分钟、实际 18 分钟），节目路线没有走完。
4. 生成：节目路线的章节名都显示“第 N 段”，后端没有提供章节标题。
5. 播放中偶尔出现“播放遇到了问题，可以稍后重试”，需要查日志；提示条的位置压在封面上，也需要调整。
6. 封面：缺少单独的封面短标题字段，标题过长时封面会降级为无字。
