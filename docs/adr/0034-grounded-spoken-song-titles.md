# ADR 0034 — 有来源的中文口播歌名与自然指代

状态：Accepted，2026-10-17。

## 问题

中文主持读不了的日文歌名即使已有曲库译名，也会在提案、持久化和快速开篇重建中丢失。缺名时把“这首歌”当歌名逐字替换，会产生“这首这首歌”。

## 决定

- 优先采用曲库明确的翻译字段 `title_zh`、`translated_title`、`tns`、`transNames`；不自动采用含义不明的 alias 数组，不建立艺人或歌曲硬编码词典。
- 在已有曲目素材整理调用中增加可选中文名、来源 id 与引文。只接收来源摘录里同时出现本曲原名和中文名的结果，校验引文确实来自该来源。缺少绑定则不采用，不另加搜索、翻译或复审调用；已有搜索次数、退出条件不变。
- 口播名随提案、Seed、MusicSegment、ResolvedTrack 的可选字段传递，重入和快速开篇沿用；研究发现的名称连同来源 id 写回当前 session 的同曲引用，供后续写稿复用。目录原名、track_ref、已发布音频及渲染计划保持原样。旧记录默认无此字段，无需数据库迁移。
- 单双人 Writer 都看到明确的口播名或缺失值，缺失不伪装成名叫“这首歌”。先由 Writer 自然组织整句；代码兜底只对已知歌曲实体及紧邻的“这首／下一首”等指代整体转换，避免重复指代。中文 UI 原稿与原始曲名保留。

## 限制与验证

来源中没有双语对应时可能仍使用自然指代，不能保证每首外文歌都有中文名。素材整理仍只在原来启用的电台和章节运行，快速开场不等待额外研究。该规则针对歌曲，人物、专辑、巡演沿用既有规则。

离线验证覆盖曲库翻译字段、无来源/伪造引文拒绝、同调用抽取、提案与 session JSON 保存、快速开篇和单双人写稿复用，以及已知名称与缺名的实际 TTS 文本。真实译名覆盖率和听感仍需新节目试听。
