# ADR 0040 — 按真实曲长续编并明确时长不足

状态：Accepted，2026-10-20；用户确认方案后实施，待 integration 验收。

## 真实问题

测试节目 `42dbb0d5-3691-4660-8ca6-e585dae5f349` 目标2100秒，完整版实际825秒，
四首歌后正常收尾。曲库有候选，但编排只选四首。原续编只在快速路径已锁定第二首时
执行，直接准备完整版会漏过；旧最低覆盖按五首×180秒封顶后取75%，再以曲数估算
抬高真实短曲总长，允许明显不足的路线完成。

## 决定

- 原有 Curator 续编同时支持只有首曲和已锁定前两首的路径。按真实音乐预算判断
  是否明显不足（低于80%），在写稿、配音和收尾前最多续编一次，复用原研究与曲库。
  传入确认曲序、已有音乐秒数、目标与剩余音乐秒数；续编朝完整预算靠近，
  继续按整首歌最接近预算的位置结束，不将80%触发线当成续编目标。
- 不新设最低歌曲数，不增加研究/评分/改写模型，不提高主持密度。已有曲长使用
  真实值，缺失才估算。现有曲目/章节上限、身份/版本、去重、主题与事实边界保持。
- 完整版追加内容须由 Curator 选定的精确主选或备选解析成功，不扩展直播路径
  同艺人任意作品的应急填充。已锁定第二首的原有连续播放兜底保留。
- 同一作品不同版本等已确认有限作品请求不为凑时长追加续编或应急歌曲。
- 一次补救后仍短但已有可播放后续时，保存 `duration_shortfall` 会话诊断和日志，
  正常完成较短节目。取消旧的曲数时长折算及其异常重试。没有可播后续仍走既有失败边界。
- 完成后的实际总长低于原目标80%时，API派生可选 `duration_notice`（目标、实际秒数），
  节目路线显示“实际约…分钟，未达到目标约…分钟”。生成中不提前提示。
  不重用 `duration_target_feasible`：该字段原意是旁白能否放入剩余预算，不代表足长。

## 验证与限制

离线覆盖无锁定/锁定第二首、四首短歌、长录音、续编无新增/失败、实际时长提示及
旧JSON恢复，并验证直接完整生成。全套回归交CI；真实听感与模型实际续编质量需新节目验收。
一次额外Curator调用只在明显不足且仍有容量时发生；可播与相关候选不足仍会得到短节目。
通知使用既有节目时间线实长，混音重叠可使最终播放总长略短。无数据库迁移，旧音频不改。
