# ADR 0031: 一次完整写稿，素材阶段守事实，成稿不逐句裁剪

- 状态：已实现；#310 最终 head `4502566` CI 全绿，已部署独立测试环境；新节目语言效果待用户试听。
- 日期：2026-10-16
- 取代 ADR 0023 的成稿逐句模型核对、改写与删句；保留其按曲目检索和素材来源校验。延续 ADR 0029 的双人单次写稿。

## 背景

用户完整试听测试节目 `ba9829b5-62b8-44e4-b1fb-c7cd8f1fcc59` 后确认播放没有硬性阻塞，最后一轮只调整撰稿。日志至少有两处单人稿删句，听感存在衔接不完整；双人存档的“某篇文章指出”和发表日期已出现在上游素材事实里。突兀的个人生活信息那一段核对无问题，不能归因于删句。

用户明确选择：文笔和连贯性优先，减少流程，接受普通措辞偏差；仍需避免把旧报道里的近期活动当作今天的事实。下一轮整体不退步即发布，不以零措辞问题为上线条件。

## 决定

```text
现有检索 / 素材整理 → Writer 一次完整成稿 → 必要代码检查 → 配音
```

- 单人路径删除 `FactChecker`、补问、规则改写、复核、风险继承、自动逐句删减和套话裁句；不再因标题未被词表识别或提到另一首节目歌曲而裁剪。相关死代码与测试一并移除，不提供严格模式或替代审核。
- `fact_support.py` 仅保留素材整理所用的来源引文、角色、限定词、人名和相似度检查。现有素材的证据归属、曲目 / 版本边界不放宽。
- 单人与双人写稿都保留完整前文用于衔接，事实仍来自素材。继续提供节目日期和来源发布日期；按曲目与人物背景的现有整理调用也收到日期元信息。报道日期不等于事件日期，不仅删除“最近”而继续声称“新专辑”。
- 素材陈述内容本身，来源信息留后台；具体评论、直接引语和争议说法保留必要归属。不要求每条事实带日期。排除与音乐无关的个人生活琐事；Writer 可以不用某条素材，不强造联系。
- 双人稿围绕现有问题和角度自然接话，允许有依据的编辑理解，不要求固定说“可以这样听”，不轮流罗列文章评价。单人提示同样偏向完整口语讲述。
- 必要检查保留证据 ID 范围、结构 / 放置合同、可读的配音文本、不承诺未播放艺人，以及未还原的相对时间和虚构主持经历。命中时省略整个 block，不留下残句；结尾仍有已有固定收尾兜底。
- “新专辑”等表达允许同一句中的明确历史年份；作品标题内的词不当作当前时间判断，标题里的年份也不能给事件定时。双人各轮独立检查，不能借另一轮的年份放行。

## 范围与代价

不增加模型调用、摘要、复审、语义判别器或新开关；不改双人槽位比例、播放器、渐进生成、等待策略、配音模型、响度、存档或已发布音频。旧节目原样恢复，新规则用于新写的稿。

旧的 `fact_check` 提供方配置仍可解析，但装配不创建该客户端，不产生核对调用；旧用量记录保持可读。`scripts/eval_narration.py` 继续提供离线规则诊断，但移除已无意义的 `--revisions` 参数，诊断不影响可播文本。

代码检查不保证语义正确，尤其不能仅凭死亡状态否定遗作发行，也不能把任意年份当作真实事件依据。事实正确性主要依靠来源、素材整理和首次写稿约束；取消复审会放过一些从前可能拦截的表述。自动测试验证调用次数、文本完整性、时间边界及降级行为；语言和内容质量以新节目试听评判。
