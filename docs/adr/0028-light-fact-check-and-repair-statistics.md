# ADR 0028: 核对定位为轻量事实兜底；保留已支持内容的修复；修复统计（离线）

- 状态：已实现并用固定文本、冻结证据和归档的真实样本离线验证；**没有新的付费调用**，不部署
- 日期：2026-10-15
- 前置：[ADR 0025](0025-story-material-and-checked-dialogue-path.md)（核对与修复）、[ADR 0027](0027-dialogue-runtime-wiring.md)
- 取代：本 PR 早先“按来源结构追溯本人采访归属”的方案（`attribution.py`）——已删除，原因见下。

## 背景：一次真实验收

2026-10-15 的人物志单段验收（见 `tests/fixtures/dialogue_portrait_20261015/`）记录为：**人物志单段经过一次局部修复后通过，用户试听认可。**
首次核对没有通过：第 5、7 轮各有一句话因 `qualifier_not_in_quote` 被拦——“他还说过，自己没学过创作……”“他说过，希望自己的歌曲能够唤起大家关于爱的共鸣。”。两句话的事实都来自方大同本人的访谈回答；这是**程序里的正则**判断短引文里没有“说”字，而 Pro 核对本身对这两句判的是“支持”。修复随后把第 5 轮的第二句整句删掉（信息损失，**不追回重做**），第 7 轮改写后通过。

## 为什么不再扩“归属规则”

上一版试图让代码自己判断“这是不是本人原话”（识别 `▲……？` 版式、发言人标签、标题里的受访者姓名……）。每堵一个口子就冒出下一个（制作人专访、联合专访、名字后缀……），本质是用正则做语义判断，而且只覆盖我们见过的版式。产品方向已确认：核对是**轻量事实兜底**，不是文风审稿，也不是版式解析器。归属、限定词、转述是否忠实，是语义问题，交给本来就要调用的那一次 Pro 核对，并给它判断所需的上下文。

## 决定

### 一、分工：模型判断语义，代码只管结构，正则只做提示

| 谁 | 管什么 | 能否单独否决或触发修复 |
| --- | --- | --- |
| Pro 核对（同一次调用，**不新增模型调用**） | 谁说的、限定词（第一次/唯一/一直/原因）、转述是否忠实、素材是否真的说过 | 仅当判为 `contradicted` 或 `insufficient`（实质事实问题） |
| 程序硬检查 | 引用的 fact id 存在；该轮的 `fact_refs` 声明了它；引文是被引事实**来源摘录里的原文**（简繁/标点不影响，去掉否定词不算）；引用结构合法 | 是（这些是代码能确定的事实） |
| 正则（`watch_notes`、`qualifiers_missing`、`roles_in`） | 把“说过/第一次/只/角色/年份”这类词标成**提示** | **否**。命中只记入 `DialogueCheckReport.hints`；没识别出来 = 未知 |

- 报告分两类：`issues`（可触发局部修复：`flagged_turns()` 只看它）和 `hints`（`unchecked` 模型没给这句判断、`role_not_in_quote`、`qualifier_not_in_quote`）。**提示不否决段落、不触发修复**。
- **响应必须完整才算数**：返回的判断要恰好覆盖所有待核对句子，每个编号出现一次，无重复、无越界。空结果、漏句、重复或越界一律视为**核对响应不完整**，与核对调用失败等价：`model_checked=false`，走既有的 `checker_unavailable` 路径——段落被拒、不配音、不计首次通过、不触发修复、不重试、不新增付费调用。（此前只要返回不是 `None` 就当作已核对，`findings=[]` 或只有越界编号时整段仍会 READY。）完整响应里判为 `not_factual` 的句子是有效判断，不会因正则命中而被否决或标成提示。核对整体不可用时，故事类段落仍**不在没有判断的情况下配音**（沿用既有规则）。
- 自然表达、主观听感、文风、无害的重排**不是返工理由**；提示词明确：`insufficient` 只用于真实的事实缺口（另一个人、程度、原因、日期、角色），不用于风格；忠实转述算支持；措辞不必与素材一致。
- 给模型的上下文：`MaterialFact` 新增可选字段 `source_title`（来源标题）和 `context`（引文在来源里的前 280 / 后 100 字，由 `verify_material` 从证据里切出，代码写入，模型不能给）。**只有该段落实际引用的事实**才附 `context`，不为没被引用的事实增加提示长度。提示词说明：访谈里的回答是受访者本人的话，请据标题和上下文判断是谁说的。上下文只是给模型读的，**不是证据**：模型给出的引文仍必须是被引事实自己的来源摘录。
- 句子下方的 `note:` 行指向那些通常需要对照来源的词，只是指针，不是结论。旧素材（没有这两个字段）照常读取。
- 不再扩采访版式规则；`attribution.py` 及其测试已删除。

### 二、修复：只有确认的实质事实问题才触发，且优先改写

`DialogueRepairer` 的提示：优先改写有问题的那个说法（去掉素材没说过的限定、归属或评价，改成素材确实说过的表达）；这一轮里已有素材支持的内容必须保留，不要为了通过核对而整句删除；只有某句话完全找不到依据、无法改写时才删那一句。仍只改被标出的轮，说话人和轮数不变；修复最多一次，随后整段复核一次（第一轮 Pro 核对暂保留，不新增模型调用）。
这次真实样本里第 5 轮的整句删除记为信息损失，不追回。

### 三、统计：四个数分开记，样本不足时不下结论

`intelligence/dialogue_metrics.py`（流水线自动统计，`DialogueStack.metrics`；每个段落也输出一行日志）：

- **首次通过率** = 第一次核对就没有 `issues` 的段落 / 走到核对的段落；
- **修复触发率** = 进入修复的段落 / 走到核对的段落（这是“降低额外修复频率”的观测口径）；
- **修复成功率** = 修复后通过的段落 / 进入修复的段落；
- **额外费用与耗时** = 修复调用 + 复核调用（费用取自带价格的用量事件，**任何一次调用没有价格则整体为未知**，不是 0；耗时是墙钟时间）；
- 另记**信息损失**（修复让被修轮少了几句）；写稿后在核对前就被拒（太长、无效）的段落按原因单独计数，**不进入任何比率**。
- **只有真正开始的修复才计一次触发**：调用预算只够写稿和初检时，修复没有调用，不计触发（记入“未通过且未修复”）。**已开始的修复，无论怎样结束**（修复无效、修后过长、超时、复核不可用、仍未通过、被取消），都结算已知的费用和耗时；费用只在每个相关调用都有价格时才给出，否则为未知（`null`），耗时总是有。被取消的段落不进任何比率（单独计 `cancelled`），但已花的修复费用和耗时仍计入额外费用与耗时；取消照常向上传播。

摘要同时给出样本量；少于 30 个走到核对的段落时 `rates_established=false`。**归档样本只有 1 个这样的段落**（首次未通过、触发修复、修复成功，额外 ¥0.0251、约 14 秒、损失 1 句；另有 1 个在随便听预算下写稿后被拒的草稿），不足以证明兜底低频，也不足以证明修复稳定有效。

### 四、回归样本

`tests/fixtures/dialogue_portrait_20261015/`：规范化素材、修复前后的稿件、两次核对结果、修复输出、三份安全用量摘要、冻结证据投影和 `MANIFEST.json`。试听音频不入库。样本无凭据，也有测试检查。其中 `check.result.json` 是**当时的真实结果**（含两条后来被降为“提示”的 `qualifier_not_in_quote`），保持原样，不改写历史。

## 验收对照（`tests/test_dialogue_check.py`、`tests/test_dialogue_pipeline.py`、`tests/test_dialogue_metrics.py`）

| 点 | 验证 |
| --- | --- |
| Pro 判“支持”即放行 | “他说过……”引文里没有“说”字也通过；“第一次/周杰伦说过/一直……作曲”等正则命中只进 `hints`，`issues` 为空、`flagged_turns()` 为空；流水线层面只有提示时 `READY`、2 次调用、不调修复 |
| 只有实质问题触发修复 | `insufficient`/`contradicted` 才进 `issues`；`not_factual` 是完整响应里的有效判断；检查不可用 → 无 issues、`model_checked=false`、段落被拒（不凭信任配音）、不触发修复 |
| 响应完整性 | 空结果 / 只有越界编号 / 漏句 / 重复 / 多出 / 负数编号 / 数量对但编号错，均 `model_checked=false`、无 issues、无可修复的轮；流水线层面：段落 REJECTED（`checker_unavailable`）、2 次调用、无修复调用、无重试、不计首次通过、不计修复触发；任意顺序的完整响应被接受（变异检查：去掉完整性判断，13 项失败） |
| 结构仍由代码保证 | 引文不在来源摘录里、未知 fact id、没声明的 fact_ref → issue；从 `context` 里摘的引文不算引文（上下文不是证据） |
| 给模型的上下文 | 被引用事实带标题与上下文，没被引用的不带；`note:` 只作指针；提示词里 `insufficient` 不用于风格、转述忠实即支持、访谈答语是受访者本人的话 |
| 归档样本 | 访谈事实 F1–F8 的上下文含提问 `▲`；当时被拦的两句在 Pro 判“支持”时通过；Pro 判 `insufficient` 的句子仍触发修复 |
| 旧素材兼容 | 无 `source_title`/`context` 的已保存素材可读取 |
| 修复提示 | 优先改写、保留已支持内容、整句删除是最后手段，原因和原轮仍在 |
| 统计 | 各自的分母、未知不为零、样本不足不称成立、与流水线接线、账本按作用域和新增事件计价；预算不够时修复不计触发；修复无效/过长/超时/仍未通过/取消时费用与耗时照常结算 |

## 仍未覆盖

- **新提示与上下文在真实 Pro 上的表现没有验证**（本批不做付费调用）：它是否对“他说过”的访谈句判“支持”、是否仍能抓住真实的归属错误、误拒/额外修复频率是否下降——都需要下一次明确安排的真实调用，且一个样本不足以下结论。
- 只检查事实不检查文风：这是有意的取舍。代价是正则提示不再兜底，真正的错误归属依赖 Pro 的判断；`hints` 留给人查看，必要时再决定是否升级为人工复核入口。
- 额外费用只统计带价格的 Ark 调用；豆包配音没有价格，不在其中。
- 动态等待策略不在本批，等后续产品讨论。
