# ADR 0025: 共享故事素材 → 双人稿 → 事实核对 → 可保存的讲述（第二批，离线）

- 状态：第二批已实现（未接入整档生成、TTS、播放器，也未启用于生产；不调用付费 API）
- 日期：2026-10-14
- 前置：[ADR 0024](0024-ark-text-models-and-dialogue-contract.md)（Ark 适配、角色配置、对话契约；对话转播放片段的限制**保持不变**）

## 目标

用固定响应走通一条完整文本路径：一段共享素材，经 Writer 写成双人稿，经事实核对（必要时只修有问题的轮），得到一段**可保存、可检查**的讲述。接入真实检索、配音和时间线是后面的批次。

## 决定

### 一、故事素材（`models/story_material.py`、`intelligence/story_material.py`）

`StoryMaterial` 是有界的素材，**不含任何台词**：`story_id`、对象与范围（录音/专辑/背景）、涉及的录音、中心问题、事实列表（至多 12 条）、编辑角度（明确是判断，不是事实）、不得外推的内容、`backstage`（目录编号、来源备注，永远不念）。

每条 `MaterialFact` 有 `fact_id`、陈述、`evidence_id`、**逐字**支持原文 `quote`、范围、对象、版本范围。`fact_id` 与 `Evidence.id` 是两个命名空间：对话的一轮引用的是事实 ID（“这一轮用了哪些事实”），事实再映射到证据。

`material` 角色（独立配置）做一次有界调用，从程序已有的证据里提炼；应用随后验证并**自己编号**（`{story_id}-F{n}`，不取模型给的 ID），丢弃：证据不存在、引文不是证据原文的连续片段、陈述比引文多出限定词（第一次/只有/一直/为什么…）或角色（作曲≠编曲≠演唱）、属于别的录音、目录类信息（转入 `backstage`）。有效事实少于 2 条则不产生素材。提炼调用失败时异常交给调用方决定，取消不被吞掉。

### 二、Writer 写双人稿，核对只修问题的轮（`dialogue_writer.py`、`dialogue_check.py`、`dialogue_pipeline.py`）

- Writer（`writer` 角色）拿到素材（只含事实 ID、陈述、编辑角度、限制和后台信息，**不含原文引文**），自己决定怎么讲、怎么接话，返回 `DialogueDraft`。应用赋予块/槽位 ID，估算时长，并校验引用：未知事实 ID 失败；`story` 块必须有引用。篇幅目标只作为提示给 Writer，**从不设下限**；只有“硬上限”会拦下失控的长稿，**修复之后会再检查一次同一上限**（修复可能把稿子写长；超出直接拒绝，也不再花一次复核调用）。
- **实际朗读的内容必须是被核对的内容。** 模型写的一轮（`DraftTurn`）没有 `tts_text` 字段，Writer 不能自由生成朗读文本；`validate_dialogue_block` 默认拒绝带 `tts_text` 的块，只有“由已核对文本做的确定性转换”才可以显式放行。朗读转换（读音、专名）留给后续批次，不增加默认的付费核对。
- 事实核对（`fact_check` 角色）把整段对话按顺序给核对者，逐句判断，因此带事实前提的问题（“他为什么一直坚持国语？”）和承接上一轮的回答按上下文判断。每句必须有判断，漏掉的当作未核对。核对者指出依据的事实 ID 和引文，**代码再验证**：事实 ID 存在、该轮的 `fact_refs` 已声明、引文是所引事实原文的连续片段、引文说到了句子声称的角色和增加的所有限定词。一个过于顺从的模型不能放过这些：代码会拦下。核对不改任何文字。
- **`story` 块在核对者不可用时明确拒绝**（`checker_unavailable`），不再依赖关键词是否命中：没有年份、创作、角色等词的客观事实句（如“他在上海长大”）也不会在没有判断时放行；拒绝发生在首次核对之后，不再花修复调用。开场/过渡/结尾这类不要求事实的块，只有在没有句子需要依据时才可能在没有判断下通过。
- 没有问题：稿件原样返回（`READY`，2 次调用）。有问题：只让 `writer` 的模型重写被标记的轮，说话人和轮数不变，被改的轮的 `tts_text` 清空，引用重新校验；然后再核对一次。通过为 `REPAIRED`，否则整段 `REJECTED`——不再追加重写，音乐继续。被标记的轮超过一半不修，直接拒绝。不默认做全文润色。
- 一段讲述最多 4 次模型调用（初稿、核对、修复、复核），材料在整档共享、单独计。任一模型失败整段 `REJECTED` 并带原因，不抛出；取消照常传播。核对者不可用时，需要依据的句子都记为“未核对”，整段不会凭信任被放行。

### 三、保存位置与读回（`storage/dialogue_artifacts.py`）

核对后的稿件存为**一份带版本的 JSON**（`dialogue-artifacts/{episode_id}/{block_id}.json`，对象存储），与播放片段**分开**——`NarrationSegment` 仍不能携带对话（ADR 0024 的显式拒绝不变）。记录含：完整的块（轮次、说话人、`fact_refs`、块/槽位 ID）、素材快照（事实、证据 ID、引文、后台信息）、状态、被修复的轮、首次核对发现的问题、调用数。读回会整体重新校验，包括每个被引用的事实都在快照里；**原始记录必须显式带 `schema_version`**，缺失（或不是整数 1，包括 `true`、`"1"`）不会被当成版本 1，直接报错；损坏、未知版本、块 ID 对不上同样明确失败。只有 `READY`/`REPAIRED` 能生成记录。

### 四、双人路径的电台预算与频率（`dialogue_budget.py`）

与 `voice.py` 里单人上限分开，后者**原样保留**（15/20/30/30/8 秒与最小填充比例不变）。目标区间（随便听 25–45 秒、唱片行 40–65、人物志 50–90、来龙去脉 70–120，夜里没有）和 `slot_share`（最多多大比例的位置可以有讲述：0.25/0.34/0.5/0.5）是**待验证的软起点**，不是用户验收过的产品参数。不要求每首歌都有主持，选取可以一个都不选；确定性选取（按种子散列），恢复时选的位置不变。语速按已通过样本 6 字/秒估算。

## 不变的约束

- 对话转播放片段的限制没有放开；`composer._narration_segment` 和 `assembly._merge_writer_blocks` 仍显式拒绝对话块。
- 没有接新 TTS，没有改播放器，没有付费调用，生产变量和部署不变。`create_dialogue_stack` 按角色配置建出 material/writer/fact_check 三个模型（修复用 Writer 的模型），尚未被装配调用。

## 用固定响应验证了什么

复现已认可的方大同样例的形状（证据为重建的夹具，不是原冻结搜索结果；稿件为实验 Lite 稿去掉歌词片段）：该稿的两个问题——“一直坚持”（素材没说，被**代码**拦下，即使核对模型说“支持”）和“更成熟”（核对模型判不足）——被找到，只重写这两轮，说话人/轮数/块和槽位 ID 保持，无问题的轮逐字不变，复核通过后保存，读回后轮次、引用、块/槽位 ID 完全一致。另覆盖：无问题原样放行、修复无效、未知事实 ID、`story` 无引用、过长、被标记轮过多、调用预算耗尽、提供方失败、取消、核对者不可用、夜间台跳过、短稿不被拒、存储键安全、记录读回的各类损坏。

## 仍需真实接口确认

这些固定响应测试**不能**说明：

1. Ark 对 `StoryMaterialDraft`、`DialogueDraft`、`DialogueCheck`、`DialogueRepair` 四个规整后 schema 的真实接受情况（第一批只验证了本地可转换）。
2. 真实模型是否逐字复制引文（`material` 的丢弃率）、是否遵守“只用素材”、是否自己带出素材没有的评价。
3. 核对者在 Flash/Lite 上遵循编号对话提示的情况，以及“一句一条引文”的规则对多事实句的误杀率——必要时要放宽到多引文。
4. 软预算数字和 6 字/秒的估算在真实配音上的准确度。
5. 提示词措辞（中文 Writer/修复提示，英文核对提示）的实际效果；本批没有做任何真实调用。
6. 真实检索产出的证据如何选出、限界后交给 `material`（本批只取前 12 条），以及“按需要为随便听获取故事”的预算。

## 本批没有做

- 素材的使用状态（未预约/未来预约/已发布/已取消）和“背景故事替代”：预算里只留了一次修复，没有替代。
- 数据库表、与时间线片段的关联、从记录恢复整档。
- 把对话放进两首歌之间的混音策略、配音适配器、缓存键。
