# ADR 0037 — 已发布节目：内容固定共享，运行状态每人一份

状态：Accepted，2026-10-19（#331）。继承 AGENTS 的“过去不可变”“只有完整物化的节目才能发布/分享”。取代原先“分享链接 = 每个访客重新生成一份”的做法。

## 背景

旧分享链接打开后，访客点播放才为自己生成一份节目：花额度、花时间，内容与分享者听到的不一样。要分享的其实是**做好的那档节目本身**。同时测试/正式环境的卷只有 500 MB，一档节目的 HLS 约 50 MB（192 kbps AAC），所以不能无限保留，也不能让发布挤掉别人的生成空间。

## 决定

- **发布 = 把一个已完整做好的节目固定下来**。流程：`POST /api/programs/{id}/publish`（或 `/api/episodes/{id}/publish`）→ 若还没有完整版先排 FULL 任务（占完整版名额）→ 完整版做好后整期一次混完（一次渲染；进度未知，界面只说“一般 1–2 分钟”，不编百分比）→ 校验 → 上线。状态记在 `published_programmes`：`PREPARING → MIXING → PUBLISHED`，另有 `REVOKED`、`FAILED`。链接**混音完成并校验通过后**才可用。`backend/wavecast/publication_service.py`，规则（限额、预算）在 `publishing.py`。
- **校验**：manifest 完整、时长不短于混音计划、每个分片都在存储里、字节的 SHA-256 与发布时记下的一致。任何一项不过都不上线，记失败原因，可重试。存下“资源清单”（manifest 键加各分片键）和总字节数；这一轮不做重建/修复。
- **一份音频，多人共用**。听众的副本是他们自己的 `LiveEpisode`（`seed_id` 与 `published_programme_id` 都是已发布节目 id，状态 PUBLISHED），时间线从源节目复制，进度、收藏、历史各自一份；**不生成、不占额度**。副本的 `program-render` 直接返回源节目的固定 manifest，不渲染；混音/导出对副本返回 409。收藏与最近都以已发布节目 id 为键。每人每节目最多一个副本；已发布节目 id 是 `pub-<hex32>`，短链 `/p/<前10位>`，与旧的 `proposal-` 前缀互不冲突。
- **谁能听**：`LINK`（知道链接的人）、`PUBLIC`（还会出现在后续的“大家都在听”）。游客和登录用户都能发布、都能公开。
- **撤回 = 不再有新副本、不再上首页；已有副本继续能听**。删除自己发布的节目等于撤回（节目库删除带 5 秒撤销，撤销即恢复）。撤回的链接对没有副本的人是 410，对有副本的人仍打开。撤回、删除都不删音频。
- **清理不会误删**：`_gc_program_render_cache` 把 PREPARING/MIXING/PUBLISHED/REVOKED 的源节目目录都列为受保护。发布过的节目不被当缓存回收。仅 FAILED 的不受保护。
- **容量预算与并发**（`check_publish_admission`）：每人同时最多 10 档（`MAX_PUBLISHED_PER_OWNER`）；全站同时最多 2 个混音；已发布音频总量不超过预算（默认卷的一半，或 `WAVECAST_PUBLISHED_AUDIO_BUDGET_MB`）；剩余空间必须容纳这档的输出、约 90 MB 混音临时空间，并**始终给生成留 150 MB**，混音途中剩余空间跌破预留也会中止。被拒绝时 429（上限）/503（忙、空间），带 `X-Wavecast-Refusal` 头。
- **下架开关**：环境变量 `WAVECAST_TAKEN_DOWN_PROGRAMMES=pub-…,pub-…`。被下架的节目：页面 404、不能新建或重开副本、副本与源 HLS 播放列表都 404、不能恢复。不依赖新增管理端点。
- **旧链接失效，不悄悄退回成再生成**：别人的 `proposal-` 节目页、`/api/programs/{id}/adopt`、旧短码都返回 410 `legacy`，页面写“这个链接已经失效了”。
- **“听过”只记一次**：`POST /api/published/{id}/listen`，播放开始时调用，按 听众+节目 去重（`programme_listens`），供后续“大家都在听”使用。

## 没做 / 限制

- 不压缩、不冷缓存重混、不做长期无人收听回收；也不迁移到对象存储。音频留在本地卷上（计划的是先扩卷）。
- 混音任务是 API 进程里的异步任务；重启会丢，记录仍是 MIXING，下一次有人看（轮询或完整版完成钩子）就会重新开始；45 分钟没完成算失败。
- 混音一次渲完。曾试过 15 分钟一步（可报真实进度），但每步都要重渲前缀并校验已冻结分片，总耗时翻倍，而且步长被发布者自己的播放位置左右（听到第 13 分钟，第一步就几乎是整期，进度条在 0 停很久再跳到 81%），所以改成一次渲完。服务里的 `step_seconds` 仍可调小，换真实进度、更长的等待。
- 数量上限、预算比例都是配置，不是产品决定。
- 旧的 `shared_copy`（按提案复制）没有调用方了，仅测试引用；之后可以删。
- 发布者自己打开自己的发布链接，也会得到一份副本（与原节目的进度分开）。
- 播放页的分享面板对副本只给出链接；对已撤回的副本没有特别处理。
