# ADR 0023: 主持词的事实要有来源；资料按实际放的曲目去找

- 状态：已实现（#265、本 PR），默认开启，`WAVECAST_TRACK_RESEARCH=off` 可关
- 日期：2026-10-11
- 关联：#195（总览）；参考 ALCE（证据对应）、Ragas（逐条事实核对）、STORM（研究与写作分工），只借方法

## 背景

人物志（久石让）实跑里，主持词把木村弓的歌写成“作曲是久石让”，把《菊次郎的夏天》的曲子放进宫崎骏电影，还有证据里没有的“九首短诗”“日本音阶”。原因有两个：

1. Writer 的资料是在选曲**之前**按请求整体检索的，每章只绑到约 3 条与这首歌关系不强的网页，缺口由模型凭记忆补。
2. Writer 被要求“只用证据”，但没有任何一步检查它是否做到。

## 决定

**一、写之后检查（`intelligence/fact_support.py`，#265）。** 每个 Writer 草稿的事实句要有来源：代码划出必须有依据的句子（谁作曲/作词/演唱/导演/发行，年份，《》里的作品名）；一次短模型调用对每个事实句返回“支持/矛盾/证据不足”，附来源编号和引文。引文由代码核对：必须是该来源里连续、完整的原文（保留否定词）；归属类句子的引文必须说到同一种角色（作曲≠编曲≠演唱≠演奏），且点名该作品；曲库只能证明“署名表演者”，证明不了任何角色。不支持的句子退回 Writer 一次，仍不行就删这一句（依赖它的后一句一并删），整块没有剩余就跳过口播，音乐继续。检查服务失败时，需要来源的句子同样被删（不放行）。

**二、写之前按曲目找资料（`intelligence/track_research.py`，本 PR）。** 路线定下后、每章写作前（后台，播放缓冲之外）：

- 已有资料里**点名这首歌**（标题、曲库中文名或专辑）的才算“关于这首歌”；只提艺人名的不算；Latin 短标题须同时出现艺人名。
- 缺什么再查：有专辑就按专辑查一次（同一专辑的曲目共用，不重复搜），否则按曲目查；人物志/来龙去脉最多 2 次，唱片行 1 次，随便听/夜里不查。
- 一次短模型调用给出最多两条“讲述要点”，每条带来源和引文；引文同样由代码核对，另外：年份须在来源里、《》里的作品名须在资料里出现过、要点不得写或翻译这首歌自己的标题。
- Writer 拿到通过核对的要点，围绕其中一条写；没有要点的中间章节**不调用 Writer**，宁可只放音乐，不写“接着听”之类的空话。结尾不依赖要点，被事实检查删空时用代码拼“这一程从《A》听到《B》”再接台标。
- 查到的资料随章节写回会话（`GeneratedChapter.research_evidence`），`/evidence` 与评审导出里可见。

**三、讲述对象与位置对齐；同一作品的版本请求（本 PR 第二轮）。**

- 要点分“这首歌本身”和“专辑/电影背景”两类：说这首歌的出处、署名、创作故事，引文所在的行（或整页的标题与开头）必须点名这首歌；同专辑的资料可以共享，但只能当背景，且不带署名。
- 没有歌的叙事章节（路线里这个位置没放歌）改为围绕后面那首实际要放的歌研究和写作，旧计划里的曲目、证据和讲述目标不再传给 Writer。
- 事实核对多一项：一句话如果靠的是路线里**另一首**歌的页面、而不是这个位置前后的歌，按“讲述对象不符”处理（改写一次，仍不符就删）；一次改写后仍在讲别的路线曲目的段落整段删除。
- 请求明确是“某首作品的不同版本”（如“Autumn Leaves 的不同演奏版本”）时，只有标题去掉版本标注后等于该作品的录音才能入选（标题只是包含这几个词的不算），池、Curator、续接、补曲和 FastStart 的第二首都遵守；版本不够就缩短路线，不用别的歌补时长。开场曲不是该作品时判定为误识别，约束取消。没有接入作品库，别名（如法语原名）不识别。

**四、节目背景故事（人物志）。** 节目级研究里常有人物/合作经历的好材料，却因“只讲点名歌曲”被挡在写作入口外。人物志现在一次性从节目级资料里提炼最多 3 个互不重复、带原文引文的背景故事（引文、角色、年份、作品名同样由代码核对，必须点名传主，不得写“这首歌”），隔一章讲一个，没有歌曲要点的章节、或写出的内容被核对删光的章节也用；每个只讲一次。另外：署名类说法的引文必须点名句子里的那个人（角色对、人错不算支持）；只说“歌挨在一起”的填充句会被删。

**五、验收后的补强（用量记录 + 三处生成问题）。**

- **核对覆盖完整主张。** 核对者对每一句都必须给出判断（事实：支持/矛盾/证据不足；其余：非事实）；漏返的句子不再视为非事实——只对漏掉的句子追问一次，仍无判断则按未核对处理（删或退回）。引文必须说出整句的限定词（“第一次”“他自己说”“所以/因此”“影响了”“一年里”“一直/唯一/所有”，以及句中点名的乐器/编制），只点名同一部作品或同一个人不算支持；“第一次/自己说/影响了/二五一、和声”等传记转折与乐理陈述无论核对者怎么归类，都必须有依据。结尾不再豁免：同样核对事实，只有核对者归为“路线描述/主观感受”的句子可以保留。“转变”“延续”这类词本身不禁。提示词顺序改为“固定规则 → 来源（按 id 排序）→ 待核对句子”，便于提示缓存。
- **已有材料进入口播。** 结尾只有一个位置的章节（最后一首的“结尾”）可以先讲一条已核对要点（歌/专辑或电影/人物，按标签），再收束路线；其余仍受核对。
- **请求的创作者范围。** “久石让为宫崎骏电影写的配乐”这类请求限定的是某位创作者的作品，同一表演者不等于满足范围。FastStart 提议的第二首只有在曲库里的专辑或标题点名了研究资料中与该创作者同句出现的作品时才保留，否则放弃（由 Curator 路线接上）；不靠模型记忆判断，也不做作品库——日文专辑名与中文作品名对不上时会偏严。Curator 之后的补曲/续接路径尚未接入此约束，是已知缺口。
- **用量记录。** DeepSeek 调用记录缓存命中/未命中输入（Chat：`prompt_cache_hit/miss_tokens`；Responses：`input_tokens_details.cached_tokens`），字段缺失记为未知而不是零；记录实际响应模型、接口、阶段，并可用 `usage_run_kind("replay")` 区分整档生成与文本重放。

## 没有做的

- 不引入这些论文的框架；不做全局事实库或知识图谱。
- 核对者与 Writer 是同一类模型，不等于独立认证；它受代码约束（引文原文、角色、作品名、年份），但仍可能偏严或偶尔放过。
- 版本区分（单曲/原声带/翻唱）只靠要点提示词，没有结构化的版本模型。
- 不改变节目时长、选曲和检索主流程。

## 影响

每章最多多 1–2 次 Tavily 检索和 1–2 次短 DeepSeek 调用（约 1.3 秒、3k 输入），在后台完成；实测一档节目的写作阶段增加约 30–60 秒，对首播没有影响。口播量下降：没有可核对内容的章节不再说话。
