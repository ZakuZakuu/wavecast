# ADR 0036 — 完整版：后台准备整档节目

状态：Accepted，2026-10-19（#204）。继承 AGENTS 的“整期是显式模式”和已有的 FULL 持久任务（`POST /api/episodes/{id}/materialize`），不改变运行时不变量。

## 背景

整档生成（FULL）早已存在，但入口藏在播放页“更多”菜单的“保存”里，叫法和“整期/完整节目”混用，必须停在播放页等，没有提醒，也没有失败与并发的边界。

## 决定

- **叫法统一为“完整版”。**“保存”并入它：不再有“保存到节目库”，因为节目库本来就收录听过和调过的节目。代码里的 materialize/FULL 保持原名。
- **状态不另存。**读自持久任务和节目：节目已 MATERIALIZED/PUBLISHED = 就绪；FULL 任务排队/运行 = 准备中；FULL 任务 FAILED，或排队/运行超过 20 分钟 = 失败；其余 = 无。进度只是已出音频时长占预计时长的估算，封顶 95%。逻辑在 `backend/wavecast/full_version.py`。
- **每个听众（游客或账号）同时最多 2 档在准备**，超出返回 429“最多同时准备 2 档”。同一档重复请求不占名额；超时算失败的不占名额，重试时先取消旧任务再重新排队。数的是活跃 FULL 任务里属于该听众的节目（`list_active`），不扫描全部节目。
- **只准备、不播放**：`POST /api/full-versions` 在建提案之前先检查名额（被拒不消耗游客额度），然后依次建提案、起节目、请求 FULL、让听众离开。游客与登录用户相同，占用同样的提案额度。
- **查询**：`GET /api/full-versions?episode_ids=…` 批量返回自己的节目的状态；别人的节目不出现。
- **提醒只在应用内**：设备记下自己请求过的节目，仅在列表非空时每 8 秒轮询；完成后顶部横幅“去听”，节目库图标上一个红点，打开节目库后清除。不做 Web Push。播放页自己显示状态，并在请求期间补一路轮询，防止事件流被代理切断。
- **入口**：播放页标题行按钮和“更多”菜单；调频页与“开播”同大的“准备完整版”。说明放在调频页新手引导（`tune-full`），不写在按钮上。

## 没做 / 限制

- 失败的 FULL 任务会让之后的渐进生成保持跳过（`_queue_progressive_generation` 对 FULL 任务直接返回），这是原有行为；用户重试即可恢复。
- 20 分钟超时只在读取状态时判断，没有后台清理；卡住的旧任务在重试时被取消。
- 进度是估算，早期（研究/规划阶段）可能长时间停在 0。
