# ADR 0035 — 完整开篇、正文讨论与收束分别交付

状态：Accepted，2026-10-17。继承 ADR 0032/0033，不新增复审或摘要流水线。

## 来自真实试听的缺口

#314 节目 db15f6cb… 长31:37，交付三段双人讨论，实际50.7/60.2/78.5秒。正文有实质内容，但首个快速桥段仅19.4秒单人，首段双人来得晚，最后配音仅14.8秒。计数计划排除了早期章节；任一短桥被当作已开篇；结尾只有20秒且提示“一两句”。达到讨论总数不等于节目结构完整。

## 决定

- 新建人物志/来龙去脉 FULL 节目，保留十秒左右的快速台呼，完整开篇独立以75秒为预算、60–90秒为写作目标。首歌后优先复用现有 FastStart 证据和 DialogueRuntime/素材/Writer/配音链路；缺材料或双人不可用时，同一位置退回单人完整讲述。目标不是下限，不强填字数，不提供范文套话。
- 在讨论计划里记录前两个实际音乐间隙对应的 `opening_chapter_ids`。首处没能交付时，最多由第二处接手，之后不追补，不重写已发布前缀。叙事章节编号不能把这两个窗口推到节目中间；后续位置不能无限重试。
- `NarrationSegment.hosting_role` 可选值 opening/closing 标记应用安排的编辑任务，与混音用的 narration_role、槽位 placement 分离。短台呼和普通报歌无此标记，不抵扣完整开篇；开篇也不抵扣原来的正文讨论目标。新计划继续按时长安排正文，旧计划 `opening_chapter_ids=None`、轻文本和 NONE 保持原策略。
- 两个开篇位置只计一次75秒预算，第二处是接手而非额外段落；正文目标独立，结尾预算45秒。曲序仍按现有“最接近目标的完整歌曲”规则拟合，目标时长不转成硬截曲，超出时 feasibility 如实记录。
- 第二处是否接手前，先通过现有配音/保存协调得到首处的实际结果；写收尾前也先完成已有稿的配音。只等待已生成内容的配音，不等待听众播放或发布，不阻塞连续音乐。
- 收尾为30–45秒（含固定结束语）的独立写作任务。使用编辑方向、实际曲序和成功配音的前文回应开头，不列歌单，不补新人物事实或新研究。最终章节不再做曲目研究，若同请求含末曲前介绍则简短可省，把空间留给最终 outro。结束语兜底仍保留。
- 双人开篇使用既有 OPENING purpose，正文使用原预算；单人完整开篇/收尾使用各自窗口，不受普通30秒短串场上限或随机文风动作约束。事实、时间、人物状态、语言和发布不可变检查保持。
- hosting_coverage 增加开篇与收尾的 delivered/pending/missed，按可播音频计。新重文本节目只有正文最低数、开篇和收尾均交付才报告 met；不足仍保留可播音乐，不假装文笔已经自动验收。无模型评分器或新增复审调用。

## 验证与限制

离线测试覆盖真实双人开篇链路、单人降级、短桥不算开篇、首处成功后不重复、TTS失败后次处接手、关闭早期窗口、正文计数独立、先配音再收束、未配音/跳过草稿不进入收尾、结束语与实际 outro 放置、旧 session 和轻文本行为。真实文笔、素材适配和手机听感仍需新节目试听；结构标记不是语义质量评分，也不能保证外部模型/TTS永不失败。
