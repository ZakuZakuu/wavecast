## 4. 最小接入方案

### 4.1 资料交接要保留“可以展开的故事”

保留现有 Evidence / TalkingPoint 的出处和对象约束，增加一个有界的故事材料对象。建议字段：

- story_id、讲述对象与范围、实际曲目/录音标识；
- 中心问题和简短的事件过程；
- 多条事实，每条对应 evidence_id 与支持原文；
- 这段为何适合节目和当前位置——明确标为编辑判断；
- 禁止外推的关系、未证实的说法；
- backstage_only：目录编号、资料管理信息、检查提醒等；
- 材料使用状态：未预约、未来预约、已发布、已取消。

事实库与讲述角度可以在一次有界提炼中输出，不要求为了字段拆成多个付费角色。每次只选择支持当前讲述的材料，不把整份检索结果无限复制到后续每一步。

先比较已有实验冻结的 Exa 材料与当前生产适配器输出：到底缺在检索命中、原文摘取、压缩，还是交给 Writer 的投影。用户接受的稿件依赖较丰富资料；只修改提示词但仍传两条目录事实，不足以复现。

实验接入配置先使用已验证可用的 Exa。Tavily 账号额度问题已知，但本轮不自动修改生产配置。搜索供应商选择应显式配置，不能在失败时静默继续花钱轮询。

### 4.2 Writer 写一段完整对话，事实检查修具体风险

建议输出 DialogueBlock：

- 稳定 block_id、story_id、对应的 narration slot；
- 有序 turns，每轮有逻辑 speaker A/B、展示 text、可选 tts_text；
- claim_refs：关联哪些事实；事实元数据不进入播报；
- 段落预计时长、表达形式和位置意图。

逻辑主持角色与厂商声音 ID 分离。不要把“主持 A：”拼进普通单人 TTS 文本。

用户明确要求保留电台之间的长短和主持密度区别。建议中段起步软范围：随便听25–45秒、唱片行40–65秒、人物志50–90秒、来龙去脉70–120秒、夜里保持无主持或少量短句。这些具体数字尚非用户验收过的固定产品参数，更不是必须达到的下限；同一台可以有短报歌和较完整的故事段。开场、结尾另设较短预算，同时控制整档出现频率，不要求每首都有主持。已通过的77–87秒样本主要用来验证完整讲述，不直接套给所有电台。

默认不加一个每段都重写全文的“润色模型”。实验已经观察到这种编辑会删掉提问，把对话压成说明文。事实检查有明确风险时，最多做一次针对受影响问答的修复；无风险就保留原稿。检查问题中的事实前提，以及相邻轮次组合后的完整意思。

一次段落预算要覆盖初稿、核对、修复和可能的背景替代，不能让每个子阶段各自有界却在外围不断追加调用。

### 4.3 配音是一个独立适配器，仍发布为一个音频资产

建议提供中立的 SpeechRequest：单人文本或有序对话、角色配置快照、语速、输出格式等。MiniMax 兼容旧单人请求；DoubaoPodcast 适配固定稿件对话。

第一版按整段提交：接收、核对全部轮次，保存完整音频和实际时长，再交给现有 materializer/混音器。轮次时间点留给诊断和后续字幕使用，播放器不必一轮一轮调度。供应商流式返回可以用来接收音频，不等于必须边返回边发布到 HLS。

缓存键包含有序播报轮次、角色与声音映射、供应商/模型、语速、格式和协议版本。保存真实用量回执、时长、耗时、缓存命中、最终是否发布。取消或超时不等于零计费。

第一版不做双供应商付费竞速，也不在豆包失败后自动再花一次 MiniMax 费用。若将来需要单人降级，要先明确稿件如何转换和总预算。

### 4.4 生成提前，长段落位置保守

首曲快速开始。路线和讲述位置确定后，尽早准备下一段材料、稿件和音频，不等歌曲快结束才排队。

沿用待完成主持占位和不可变发布前缀。超过最后安全时限仍失败，才跳过该段继续音乐；跳过为最终决定。记录这是否让节目退化为只有报幕，避免“播放没断”掩盖内容失败。

长对话没有可靠的人声时间信息时，第一版优先完整放在两首歌曲之间；有可信窗口再做有限叠加，不默认将长段落盖在主唱上。可以复用现有合法的编排能力，不承诺任何歌曲天然有足够长的纯音乐背景。

整体时长计入实际语音和混音重叠。固定歌曲不应为塞进对话被随意截断；路线规划可减少后续选曲或接受合理时长偏差。

## 5. 从提案到收听反馈：职责与模型分配

完整闭环：用户兴趣或主动请求 → 选题/提案 → 曲目与资料核实 → 路线和素材 → Writer → 事实检查 → 配音与编排 → 收听反馈和可复用选题线索。

首页批量与用户主动调频属于同一个提案职责的两种方式。首页需要同批差异和相邻发现；主动请求需要忠实兑现意图。提案传递中心问题、对象、station、范围约束、已有来源线索和待核实项，不能只把标题/简介再拼成一段自然语言。

当前首页10个库存、6个展示，已有按额度补货和轮换机制，暂沿用。选题尚未点播时不做整档昂贵研究。已有节目调研发现的公开资料和有价值问题可以形成候选线索，和用户兴趣结合供下一批使用；先保存出处和关联，不引入复杂知识图谱或新的自动代理。事实需要来源支持，热度或点击不能成为事实证据。

提案职责决定“节目值得听什么”；调研交付可用的具体事件/细节及证据；Writer决定本段如何展开与接话。不额外增加固定必经的“策划模型”，也不要求调研预先写每轮台词。调研按整档共享，曲目解析后再绑定录音专属材料，缺口补查受总预算限制。

## 7. 本次零付费编排探针

在独立临时目录导出上述 SHA 的源码，不改变仓库。直接调用最新 `plan_episode_mix` 和真实 Pydantic 类型；用两个固定音乐时长 274/292 秒、一个 88 秒语音资产描述进行检查。语音长度参照已完成方大同音频并向上取整；音乐是结构性测试夹具，不代表成功下载了方大同音源。

结果：

- RadioScriptBlock 和 NarrationSegment 均能承载 88 秒，不受底层 300 秒容器限制。
- 规划器保留完整 88 秒。
- 与只有首曲的规划相比，10/30/90/180/250 秒处的首曲增益抽样相同；这与 #297 修复一致，不构成所有前缀的完整证明。
- 默认缺少人声信息时，对话从 269 秒开始，下一首在 352 秒开始，对话在 357 秒结束：默认仍有 5 秒首尾叠加。
- 使用现有 ArrangementDefaults，把 outgoing_voice_overlap_seconds 与 bridge_incoming_fade_seconds 设为 0，完整桥段可处于两首之间，断言通过。实际产品还需把这项策略按段落传递，不能直接全局改变所有短口播。
- 新语言模型/TTS/搜索调用：0；没有音频渲染、后台生成、持久化往返或 HLS 发布。

这说明混音器有可复用的接入点；不能据此宣称实时主持丢失已经全部解决或长对话已经正式上线。
