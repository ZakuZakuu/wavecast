# 调频页改版（2026-10 第二轮）

起因：朋友第一次试用，说输入框不明显（好几次忘记写）、也看不出五个台有什么不同、不知道怎么写。设计在 Claude Design 画布“调频改版”页（Tune7 / TuneGuide2 / TuneGuideSwipe / TuneGuideExpand）反复评审后定稿，下面是定下来的规则与理由。代码在 `apps/web/components/tune`、`lib/{stations,station-guide,station-poster,tuner}.ts`。

## 页面

- 顺序不变：拨盘面板、“想听什么？”输入框、时长/主持两个胶囊、开播。输入框不放最上面（不方便点）。
- 面板：台色渐变底，左边 FM 标签、台名、一句话、“电台指南 ›”，右边一幅大海报盖在面板上（凸出上沿和右边，不出屏幕；只用两层阴影，没有白边），底下是刻度窗。刻度窗里台与台约 123px 一个（28px/MHz，`PX_PER_MHZ`；23 时切台动画太快，32 时邻台名字被边缘吃掉），选中时左右各露出一个完整的邻台。窗口两端是按钮：点一下切到上一个/下一个台（第一个台左边、最后一个台右边点不了），拖动照常；电台指南里的刻度窗是同一个组件。连点两下是走两个台（`useTuner.step` 从正在滑向的台继续）。
- 输入框加高到两行，台色描边外加光圈，页面下半垫一层很淡的台色光晕，让黑色的开播按钮不孤零零落在冷灰底上。黑色保留：全 App 的主按钮都是黑色，调频页单独换色会不一致（评审过台色深色/暗色/描边三种，都不如保持黑色）。
- 示例写在输入框里：空时是灰色示例，换示例按钮把下一个示例填进框里（可改）。空输入开播写“随便放点”，写了字变成“在 FM xx 开播”。
- 时长和主持：两个等宽胶囊，点哪个就在它下面弹出小菜单直接选（时长两档；主持三档，每档一句说明，当前台的默认档带“xx默认”标记）。主持只在用户动过时才发给后端（`host_mode`），见下。
- “准备完整版”：开播右边的圆形小按键，图标是“加入队列”（不用下载图标）。点了转圈，做好打勾；同时已有2档在准备时变灰并提示。第一次出现时由 `lib/guide` 的 `tune-full` 指一下。
- 没有“两个台之间”这个状态：松手一定吸附到最近的台，开播永远按最近的台算。
- 第一次进调频页落在唱片行（`FIRST_VISIT_STATION_ID`；它的写法最好学，空着开播也有内容），之后记住上次的台。`STATIONS[0]`（随便听）仍是未知 id 的回退，台的频率顺序不动（台呼录音、已生成节目都依赖它）。

## 切台

海报、台名文字、面板颜色都只取决于“离当前频率有多远”（`lib/tuner.ts` 的 `stationBlends`/`tintBlend`/`posterPose`），与方向无关：手指停住就停住，回拖就倒放。离开的海报沿水平方向微微向上飞出屏幕（略放大、转一点角度），新的台从同一位置飞回；两张错开，中间一瞬卡片上有一层杂音；文字渐隐渐现；颜色在最近两个台之间混合。减少动态：不飞，直接换。

## 海报

每个台固定一幅，用 App 里真实的封面渲染（`lib/station-poster.ts`，参数在画布上选定）：随便听=调谐器（裁切）、唱片行=磁带、人物志=琴键（四周留边，不被圆角截到）、来龙去脉=等高线的局部（圆心略偏右上）、夜里=月亮。

## 电台指南

点面板里的“电台指南”（也可以点海报或面板的空白处；滑动不算点），面板向上、向两边撑开成一页一个台，底下页面虚化；海报变大但仍凸出。每页：台名、“可以告诉它……”（该给它什么）、一句定位、主持几档、三个“什么时候用”的场景。点一条＝选这个台并把写法填进输入框，不开播。滑动卡片或拖底部刻度窗＝切台（与页面共用同一个 `useTuner`，所以没有“预览”；“选择”只是收起，页面就停在当时那个台）。出口有两个：底部“选择”，以及点卡片的上半部分（避开按钮、刻度窗和写法）——进来时点的就是差不多的位置；没有 ✕。收回的动画期间点击已经归页面（马上再点卡片会再次打开）。第一次进来自动展开，多一条“左右滑动，看看每个台”，之后不再自动弹（`lib/station-guide-state.ts`，账户页“重看新手引导”会重置）。

### 怎么分五个台（给用户看的分法）

按“你手里有什么”：

| 台 | 手里有 | 动作 |
|---|---|---|
| 随便听 | 一种心情或一个场景 | 放 |
| 唱片行 | 一首喜欢的歌 | 挖 |
| 人物志 | 一位歌手 | 讲 |
| 来龙去脉 | 一种风格或一个问题 | 讲 |
| 夜里 | 一个想安静的时候 | 不说话 |

随便听接的是状态，唱片行接的是作品。

### 示例写法（`lib/station-guide.ts`）

每一条都在测试环境用真实模型和真实音乐目录跑过提案这一步（不生成音频、不配音），得到了合适的首曲和节目方向，再写进去。改文案前先重跑一遍：一条不再能出好节目的示例，比没有更糟。已知：

- “来点我平时不会听的歌”要有口味记录才会真的跳出舒适圈；没有口味记录时它会走得很远（试过自由爵士），所以放在随便听的最后一条。“没听过的”会放用户常听的歌手，“换个口味，但别太冷门”仍停在原来的风格，都没有采用。
- 提案偶尔失败（`proposal_count_mismatch`，约6/31次，多在抽象或较长的写法上），见 [#333](https://github.com/ZakuZakuu/wavecast/issues/333)。

## 主持（`host_mode`）

后端 `ProposalGenerationRequest.host_mode`（可选）。优先级：用户动过的主持控件 > 请求里的明确字样（“只听歌”“多讲一点”）> 台的默认（夜里无、随便听/唱片行轻、人物志/来龙去脉多）。控件选回台的默认档，就等于没动（不发）。“纯音乐”这类只是描述音乐的字样，不会盖过用户的有意选择。

## 矮屏与浏览器

- 刻度窗不会停在两个台之间：卡片上的点按不再打断正在进行的切台（滑动一旦成立才停下），并且有一个兜底——停下 250ms 后若不在台上就吸附到最近的台（`use-tuner.test.ts` 有回归测试）。
- 电台指南在矮屏（浏览器带着工具栏，常见 700–760px）：高度 <800px 时去掉“一句定位”那段、各处收紧；还放不下的在卡片里滚动，底部渐隐并有一个向下的小箭头提示还有，避免一行刚好切在边上被当成到头了。按钮和刻度窗不动。
- 时长/主持菜单：向下没有位置时向上展开；两边都放不下就取较大的一边并让菜单自己滚动（避开底部导航和迷你播放条）。
