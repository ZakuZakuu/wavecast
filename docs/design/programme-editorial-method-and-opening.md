# 节目编辑方法与开篇优化

日期：2026-10-16（北京时间）；实施更新：2026-10-17。状态：用户已同意实施，开篇改动待 CI 与测试环境试听；历史研究与实际决定分别见下。

这是设计记录。当前任务与线上状态仍以 [PROJECT_STATE](../PROJECT_STATE.md) 为唯一入口。第1–8节保留讨论/研究时的上下文；实际落地取舍见 [ADR 0032](../adr/0032-editorial-opening.md)。本期案例不直接作为模型范文。

## 1. 用户目标与范围

上一轮 #299–#310 已通过 #311 发布正式环境。播放已没有用户认定的硬性阻塞，仍有文笔和组织问题，用户希望下一轮先聚焦开场：

- 当前第一句多为固定报台、报歌，缺少本期特色。
- 第一首与第二首之间多为简单串场，错过建立主题和整期脉络的窗口。
- 希望整期成为有编辑意图的连续节目，歌曲之间有值得听的关系。
- 文笔、自然度和完整性优先；保留基本事实底线，尤其避免把旧报道中的近期事件说成今天正在发生的事。
- 用户先要求讨论，确定后再实施；讨论后又要求先保存记录，再检查一期真实节目。不要把本记录误报为已完成实现。

当前工程范围仅开场。全期方法用于指导设计，不代表本轮授权全面改造选曲、正文、播放器或生成架构。台标音乐只留作 bonus。

## 2. 已确定的共同编辑方法

核心：从听众兴趣与实际材料中，找到值得组织的收听方向，让歌曲与必要的讲述共同完成一次收听。

1. **明确收听意图。** 选题是范围，还需要具体方向：听众为什么值得听、希望获得什么、哪些相关内容可以舍弃。方向可以是问题、观察、发现路线或情绪体验。
2. **研究与方向相互校准。** 带着初步兴趣查作品、歌词、创作背景和可靠本人表达；材料不足就缩小或调整切口，不先定结论再强配证据。
3. **选歌兼顾内容与音乐。** 歌曲可以提供例子、不同侧面、情绪延续、变化或呼吸。保持歌曲本身的欣赏价值，不把全部歌曲都变成论点证明材料。
4. **用曲序形成连续性。** 依据内容安排延伸、对照、转折或情绪流动。叙事单元可以包含多首歌；不要求每首歌都配一段主持，也不硬套起承转合。
5. **口播有明确任务。** 提供背景、接住刚才体验、打开新角度、解释后续安排、收束；有必要时出现。事实来自材料，作品解读有可指认依据，编辑可以组织作品间的联系。
6. **开场建立可兑现的期待。** 前两首附近让听众逐渐进入本期。具体披露多少取决于已确认的素材和安排，不承诺未确认歌曲、故事或结论。
7. **结束回应实际收听。** 回扣真正听过、讲过的内容；可以留下认识、问题或情绪落点，不要求每期给出确定答案。

这些是编辑判断的方法，不是强制输出格式。模型保留角度、语言、结构和细节选择的空间。不能靠方法论保证所有模型输出的文笔；需要用实际文本与试听验证效果。

## 3. 类似 skill 的组织方式

用户明确偏好高层方法论，反对明显的完整范文进入模型上下文后被机械模仿。

- 一份共享编辑指南；电台各有简短定位；本期再有具体意图与任务。
- 五个电台的定位可放同一配置表或短说明，不维护五套完整、重复的制作提示词。
- 提案、编排、Writer 各接收与本职相关的指导，不让所有调用装载整本指南。
- 小样例仅在原则难以表达时少量辅助；方大同完整案例保留给人类讨论、评审，不直接注入生产提示词。
- 不新增通用 skill 引擎、模板匹配、范文相似度打分、模型复审或反复改写流水线。
- 电台定位是默认值；用户明确要求、具体选题和可用材料决定实际表达。

| 电台 | 默认编辑取向（设计方向，非新实现事实） | 主持的主要作用 |
| --- | --- | --- |
| 人物志 | 从切口逐渐认识人物或作品 | 细节、不同侧面的关系 |
| 来龙去脉 | 发展、联系与探索路线 | 解释关键关系 |
| 唱片行 | 围绕兴趣发现作品 | 背景、推荐理由、听歌线索 |
| 随便听 | 亲近感、口味一致性与适度新鲜 | 轻量陪伴，按需点出联系 |
| 夜里 | 情绪、强度和安静的连续性 | 少量主持或无主持，尊重留白 |

重文本验收理解是否推进、主题是否具体；轻文本验收选曲是否有心意、变化是否自然、口播是否值得出现。轻文本不强制听众复述论点，也不统一插入长篇主题说明。HostMode.NONE 继续无主持。

## 4. 开篇设计与最小落地方向

- **首曲附近短开场：** 快速进入本期，建立兴趣。台呼可固定，内容表达应随节目变化；问句、观察、背景等均可，不指定统一第一句。
- **第一首后／第二首附近：** 重文本节目可用完整开篇承接首曲、明确切口和听歌方向，再进入下一首。轻文本按需简短连接或留白，两处不重复自我介绍。
- 十秒上下的短开场、半分钟至一分钟的完整开篇只是讨论中的试听起点，不是已确定的时长、字数下限或跨电台硬标准。
- 文本优先在已有提案阶段准备；第一首播放时尽早完成后续开篇及配音，避免增加首屏等待。
- 复用现有安全位置。兼顾实际窗口与完整讲述，不压住演唱，不拆成残句，不修改已播或已可跳转的前缀。
- 正常收听争取在前两首附近完成主题建立；极短首曲、快进、超时等情形仍保持音乐连续。
- 优先利用已有提案简介、编辑方向、已播短开场、已确认首两首与当时可用的可靠材料。不要为开篇等待完整研究，不凭歌名臆造听觉、歌词或背景事实。
- 仅确有缺口时补最小上下文字段；不预先增加独立规划调用。完整开篇本轮先以现有单人路径验证，不为此调整双人比例。

## 6. 方大同案例：只用于人类评审

用户最初举《爱爱爱》《特别的人》，并提到其他播客把后者解读为热烈中有理智克制。随后明确要求独立检索、选曲和组织整期，不能只围绕用户给的两首发挥。

检索后提出的整期切口：**真心表达出来之后，怎样成为两个人的关系？** 用户认可这样的节目更完整。此策划不是实际生成节目，不强制应用到其他选题。

| 顺序 | 作品 | 候选编辑作用 |
| --- | --- | --- |
| 1 | Love Song | 结合本人访谈，从真诚表达出发 |
| 2 | 小小虫 | 歌曲角色笨拙的靠近与喜剧性的机会，增加亲近感 |
| 3 | 每天每天 | 日常陪伴中意识到超越朋友的感情；不直接说成情侣稳定生活 |
| 4 | 三人游 | 付出、理解和等待未必形成期待的关系，保留复杂感受 |
| 5 | 够不够 | 家庭、物质期待与彼此衡量方式；不简单指责某一性别物质 |
| 6 | 特别的人 | 热烈投入与双方参与、耐心和磨合；“清醒地投入”是编辑解读 |
| 7 | 为你写的歌 | 从表达心意回到邀请回应，与首曲呼应 |

建议在 Love Song 后建立主题，小小虫与每天每天之间可轻接或连播；三人游引入关系位置的问题；够不够与特别的人之间值得展开；尾曲前收束，再让音乐完成结束。

“约半小时”是策划目标；具体录音、曲库可播性、时长及音频衔接未核验，没有实际重听整套录音。判断主要依据歌词与文字资料，不把编曲/唱法的未经试听细节当论据。

《爱爱爱》可服务另一条线：电影、小说、情歌怎样影响爱情期待；不因用户举过它就强塞进本期。作品角色、他人作词和艺人本人观念应区分，不把曲序写成他真实恋爱经历或思想演变。

## 7. 恢复实施时的步骤与验收

1. 先结合当前真实节目检查的新反馈，确认开场范围仍适用。
2. 整理短编辑指南及五台定位，以方法为主，不向模型注入本案例完整台词。
3. 接入现有提案与开篇 Writer；检查上下文、适用的 slot 与启动/生成时序，仅补必要信息。
4. 用人物志和一个随便听轻选题检查文本，再检查配音与插入；不要求所有电台出现长主题说明。
5. 对非平凡代码改动补必要测试，验证首曲速度、连续播放、及时性、去重、旧节目恢复和已发布前缀不变。
6. 一份集中 PR → CI → integration 测试部署 → 用户试听 → 通过后发布 main；不要直接把本讨论作为下一轮生产部署授权。

验收重点：重文本前两首附近能建立具体主题；轻文本能自然进入收听；两处开场各有作用而不重复；音乐连续，事实底线和旧节目保持。

本轮不扩展为全文改写、全选曲架构重构、五套独立完整提示词或额外模型审核。台标音乐只记录为后续可能的 2–4 秒预制品牌声音，当前不实施。

## 8. 2026-10-17进一步代码研究：明早实施前的建议

本节是研究方案，**没有接入生产提示词，也没有实现开场改动**。用户睡前授权的是外文口播/空稿修复合入测试，以及之后继续研究；开场待明早讨论后实施。口播缺失的配置故障和外文问题先独立解决，不能靠加长开场掩盖。

### 8.1 开篇目前为何容易空泛

不只是模型文笔问题：中文提案忽略了模型的`opening_host_note`，首个A→B Writer又只拿到用户原始topic和两首歌的身份，拿不到卡片简介、编辑方向和已经播出的短开场。与此同时，这个Writer的任务是普通bridge，`voice_instructions`还可能随机抽中plain或要求具体事实的move；空证据限制使它只能报歌。仅调高目标秒数解决不了这些信息和任务的冲突。

现有单人窗口还有电台上限：人物志/来龙去脉30秒、唱片行20秒、随便听15秒。把FastStart的24秒直接改成45秒，仍会被`window_for`压回30秒。建议第一版先在现有上限内做好内容，不同时重构时长分配；若实际文本确实需要更长，再只讨论开篇的窗口。

`voice_instructions`还会给普通块字数下限、禁问句/句式、虚构口吻样例等较多指导。开篇需要的是明确编辑任务，不是再叠一层硬规则：应避免这些旧指导覆盖开篇任务，不为凑`MIN_FILL`扩写，也不强制某种修辞。人物志当前定位写“一位歌手的路”，但“爱情观”等选题不必写成职业年表；电台定位是默认表达方式，具体问题优先。

### 8.2 两处开场各完成什么

| 位置 | 编辑任务 | 可依赖的内容 |
| --- | --- | --- |
| 首曲附近短开场 | 让人知道这期为何值得听，迅速把注意力交给音乐；台呼可固定，主体不固定句式 | 本期兴趣、提案方向、实际首曲身份；不引用未经研究的歌词、听觉或人物事实 |
| 首曲后/第二首前 | 接住首曲，说明本期具体想探索的方向，给下一首一个自然的位置；不再重复欢迎语和完整报台 | 提案简介/方向、确认的首两首、已确定会播的开场原文；有证据才讲作品细节 |

区别不是规定每段必须说三件事，也不强制用问句。人物志等重文本优先完成主题建立；轻文本只保留值得说的连接和收听理由；NONE不生成主持。先在人物志上用约25–30秒、轻文本沿用短窗口试文本，作为试听候选而非字数或时长下限。第一段仍保持短，不把完整主题论述挤到首曲上方。

短开场也不应只是“完整报台/报歌模板＋模型备注”：那样第一印象仍然相同，文本反而更长。本期特有的导入可以先出现，台名简短交代，报歌按需要取舍；不强制固定顺序或增加开场长度。品牌身份的稳定与每期内容的不同可以同时成立。

提案是编辑意图，**不是事实来源或已经兑现的曲序**。例如“想比较个人作品与乐队编制”可以是本期兴趣，不能无证据断言某录音有某种爵士切分，也不能承诺后面一定会放某首还没确认的歌。材料不足时表达探索方向，后续研究允许调整；不提前宣布结论。

### 8.3 最小实现入口与取舍

1. **先整理方法指导。** 以本文件第2节为基础压成简短共享指导，五台只给定位和文本密度的默认差异。分别给Proposal和开篇Writer各自需要的部分；不把全份指南、完整方大同范文或五套长提示词塞进每次请求。现有`voice.py`里的随机move和虚构口吻样例不应叠加约束开篇，开篇任务优先；普通正文暂保留现状。
2. **启用已有的中文开场备注。** `_opening_narration_text`优先用合适的`opening_host_note`，沿用现有身份解析和口播名称转换，`compose_opening`保留兜底。修改Proposal的备注要求为本期兴趣导入，避免固定句型、无依据曲目评价和重复报歌。注意：备注生成时首曲尚未通过曲库解析，候选可能轮换；它应对候选选择保持有效，不能假定某首已被选中。超长/不可朗读/缺失时用完整的兜底文案，不截成半句话。
3. **让首个Writer看到编辑意图。** `EpisodeSeed`已有`short_description`，`EpisodeOrchestrator.start`当前没有把它持久化到`LiveEpisode`，所以异步Writer丢失了这部分信息。优先只增一个可选、向后兼容的节目编辑背景字段，把已有简介持久化；标题/topic已经存在。先验证简介是否足够，不预先新增整套编辑计划模型、阶段状态和路线字段。只有具体样例证明缺少必要方向，再传现成`editorial_route`，仍标成意图而非事实。
4. **开篇任务与物理槽位分开。** `author_fast_successor_narration`仍写入原有before-track槽位；用明确的开篇任务替代“普通短串场”目标，避免随机move覆盖主题任务。不应为获得开场语气把物理槽位强行标成`is_opening`：该标记参与放置逻辑，语气与播放锚点是不同概念。具体采用一个可选开篇上下文参数，还是从现有chapter目标生成指导，以最少重复规则为准，实施时定稿。
5. **传入已确定的短开场原文。** 第一桥段目前没有传`previous_committed_context`。应取调用开始时已有、确定会播的开场，避免再次欢迎/重复主题；不等待未完成稿、不传已跳过旁白、不增摘要调用。主题信息通过正常持久化状态到达Writer，不让它反查提案仓库或依赖进程内缓存。
6. **分享、默认卡片与旧数据一起检查。** `_shared_opening`当前会另造模板，不能只修直接生成入口。新提案若需让分享副本复用简短备注，可增加一个可选的原备注字段；先确认是否必要，避免从完整台词用正则“拆回”备注。旧提案/旧节目缺新字段时保持原稿或已有兜底，不重新研究或重写已发布内容。NONE和用户明确的少说/多说要求继续优先。

不建议为第一桥段新建研究调用。FastStart虽然做过快速检索，但`prepare_fast_successor`当前只返回音乐和占位，没有持久化那份证据；不能假装开篇Writer已经能读到它。第一版可以只表达主题与收听方向；确实需要作品细节时，另行评估如何复用已存在的证据，而不是补一个查询/复审流水线。

若实际前两首明显偏离提案切口，Writer不应事后硬编两者关系。先收窄到这两首确实能承载的收听方向；若这种偏离反复出现，下一步是把同一份编辑背景透传给现有FastStart选第二首的调用，让选曲也理解意图，不是增加一次模型选曲。完整Research/Curator同样目前主要读取原始topic，故本轮开篇改好不等于整期编辑脉络已贯通；那部分留到后续正文/编排迭代。

### 8.4 时序与混音：已核实的限制

```text
生成提案（已有模型调用）→解析首曲→点击开播
  →短开场TTS（当前请求等待预算8秒，可超时省略）
  →FastStart确定第二首并持久化音乐
  →首个Writer与其TTS
  →完整Research/Curator继续准备后续路线
```

8秒是等待TTS返回的预算，不是允许的音频长度；`planned_duration_seconds=8`也不能替代实际音频时长。不要因短开场更多样就扩大开播等待预算。首个Writer目前用FAST档（15秒预算），其配音在完整路线研究前被await；不应把它改成重研究或更慢的多轮调用，也不在本轮重构worker并发。

`arrangement/planner.py::_opening_host_offset_seconds`优先找首30秒内可容纳整段的器乐窗口；**若无timing、或有timing却找不到足够窗口，现有策略仍回退到约第6秒叠播**。因此“总能避开演唱”不是当前实现保证。第一版保持开场短，验证实际配音长度与已有窗口；不能承诺加长后自然安全。若试听/离线时间线证明短句也会明确压住主唱，再针对开场决定缩短或省略这一处叠播，不扩成整套混音重写。

首曲或桥段的音频前缀一旦发布，晚到文本不能追插。快进、首曲极短、取消、TTS超时导致开场未出现时，第二首仍可播放，不靠等待主持完成来兑现“前两首建立主题”。这是正常路径的目标，不是每种操作下必须强塞的硬规则。

### 8.5 怎么验收，避免又做出一套模板

- 人工读稿：听完开头能说出本期具体想听什么，以及下一首为什么在这里；若只剩歌名、艺人履历或“音乐很丰富”，还没完成目标。
- 两处不重复：短开场引入兴趣，第一桥段推进理解；开场缺席时桥段仍自足，开场已播时不重做欢迎。
- 事实与方向分清：日期/人物状态底线不退；不把歌词角色直接当艺人恋爱经历，不把提案设想当音频分析结果或确定曲序，不为了主题硬编首曲含义。
- 离线用人物志（方大同/椎名林檎）、来龙去脉、唱片行、随便听和NONE检查上下文、任务与时序；不要为测试默认触发六期付费生成。
- 后续只需一份重文本和一份轻文本的新节目人工看稿/试听。评价主题是否具体、语言是否自然、首曲是否仍快开、桥段是否及时，不做范文匹配/机械评分/字数达标。
- 自动回归覆盖：中文备注被使用、最终首曲与候选轮换、分享/旧提案兼容、编辑背景跨进程保留、第一桥段收到已有开场、NONE零主持、超时/取消/快进不阻塞、已发布前缀不变。开场相关测试分布在`test_program_proposals.py`、`test_stations.py`、`test_staged_runtime.py`、`test_generation_worker.py`、`test_arrangement.py`及节目流API测试中，先沿用这些入口。

台标音乐仍留到后续：优先一份权利清楚的固定短音标，通过现有单一节目音轨混音，控制旁白可懂度和响度；不单开浏览器播放器，也不每期重新生成。当前不选素材、不购买、不接入。
