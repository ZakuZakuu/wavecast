# 英文口号的播报消歧

2026-10-19。测试节目中，全大写的 `NO MUSIC, NO LIFE?` / `NO LIFE NO MUSIC`
被反馈读成了化学词；保存稿件没有单独的发音文本，使用豆包双人播客模型。

沿用 `text` / `tts_text` 分离：展示原文、事实引用与已发布音频不变。新写稿的
公共指引要求英文完整句子和口号采用正常大小写，保留真正缩写及专名。
代码仅对上述两个方向的完整 music/life 口号作大小写消歧，兼容逗号和空白；
不猜测孤立 NO 的含义，不统一转小写，不扩展成通用英文词典。

双人稿每轮经过已有确定性 `to_spoken_form`，不再只对包含不支持字符的轮次处理。
这也让已有年份读法、可说歌名转换在纯中英文对话中生效；不另加模型调用或复审。
相同文本不额外存 `tts_text`，不同发音文本自然进入已有音频缓存键。
旧记录加载、缓存及已发布节目不批量改写。本次不扩展到 #317 的和弦符号转换。

## 语音对照

先预览，不访问供应商：

```sh
uv run python scripts/doubao_podcast_case_probe.py
```

有 `DOUBAO_PODCAST_API_KEY` 时，显式合成三个短样本（全大写、正常句式、小写）：

```sh
uv run python scripts/doubao_podcast_case_probe.py --run-live
```

固定同一段中文语境、播客模型与双人音色，不调用写稿、研究或节目生成，不重试；
输出 WAV 默认在 `/tmp/wavecast-podcast-case-probe/`。不要把 key 放进命令参数或仓库。
当前开发会话未注入播客 key，只有离线转换、发送文本、恢复及缓存回归验证；
大小写调整后的真实发音尚待此短测或新节目试听，不把合成成功当作听感已验证。
